# 🤝 ProfeAI Contribution Guide

First of all, thank you for considering contributing to ProfeAI! It's because of people like you that this project continues to improve.

## 🚀 How to Get Started

### 1. Reporting Bugs
- Before submitting a new issue, please check the [existing issues](https://github.com/elecodes/ProfeAI/issues) to make sure it hasn't been reported yet.
- When opening an issue, use the **Bug Report** template to provide all necessary details (OS, version, reproduction steps).

### 2. Suggesting Features
- We love new ideas! Please open a **Feature Request** issue to discuss your proposal before starting to code.

### 3. Local Development
To set up ProfeAI locally, follow the instructions in the [README.md](README.md#🚀-instalación-y-uso).

Key commands from the root:
- `npm install`: Install all dependencies.
- `npm run dev`: Launch both frontend and backend.
- `npm run test`: Run unit tests.

## 🛠️ Pull Request Process

We want to make your contribution process as smooth as possible. Here’s the workflow:

1.  **Fork and Branch**: Fork the repository and create a branch for your fix or feature (e.g., `fix/login-error` or `feat/new-lesson`).
2.  **Commit Messages**: Follow [Conventional Commits](https://www.conventionalcommits.org/) if possible (e.g., `feat: add new dialogue flow`).
3.  **Tests**: Ensure all tests pass (`npm test`) before submitting.
4.  **Open a PR**: When you open your PR, a **Checklist Template** will appear. Please fill it out!
5.  **Welcome Bot**: Our automated bot will greet you and provide specific guidance for your PR.

## 🎨 Coding Standards

- **Frontend**: We use React + Vite + Tailwind. Prefer functional components and hooks.
- **Backend**: Node.js + Express. Keep business logic in `services/`.
- **Formatting**: We use ESLint and Prettier. Your code will be automatically checked during the PR process.

## 📜 Code of Conduct

By participating in this project, you agree to abide by our code of conduct: be respectful, inclusive, and professional.
